## 需求概述

用户对"视频自动匹配同文件夹字幕"的识别逻辑不满意：字幕文件名前常被加上装饰符号/组名前缀导致识别不了；同时现有"宽松前缀/带分隔符"匹配存在把 `StarWars 1977.srt`、`StarWars II.srt` 这类衍生内容错配给 `StarWars.mp4` 的误匹配。用户要求设计一个全新的智能匹配算法：以视频名为基准，综合文件名评分与字幕时长二次校验，为视频匹配同文件夹下最合适的字幕；宁可匹配不到也绝不强行错误匹配。

## 澄清确认后的范围

1. 彻底移除现有"同文件夹字幕扫描设置"中的前缀匹配三选一（exactOrDelimited / startsWith / exactOnly）与大小写开关，连同设置界面一并删除，统一走新算法。
2. 允许读取字幕内容做二次校验：仅对文件名初筛后的少数候选解析字幕时间轴，与视频时长比对（接近加分、明显不符降权/否决），读不到或解析失败按信息缺失中性处理，不得误杀有效字幕。
3. 评分不足即视同无字幕：自动加载与自动绑定只在置信达标时发生；低置信/不合格字幕仍应在"字幕管理"面板中列出供用户手动挑选，不得因过滤过严导致用户无法手动补救。
4. 多候选按语言权重排序：中文(zh/chs/sc 等) > 无语言标记 > 英文 > 其他；排序前二分别作为主字幕与副字幕（双语场景）。

## 核心功能

- 新的文件名解析与评分引擎：归一化、去装饰前缀、识别语言/发布 tag、资格判定与置信评分。
- 轻量字幕时长解析与二次校验（srt/vtt/ass/ssa/lrc 行扫描取最大结束时间；sup/idx/scc 等图像字幕中性处理）。
- 双通道扫描结果：全部潜在字幕（供手动面板）+ 高置信自动匹配候选（自动加载/默认绑定用）。
- 各调用方（播放器自动加载、媒体播放服务、文件夹/压缩包导入绑定）统一接入新策略。

## 技术栈

- Dart/Flutter（沿用现有架构，无新增第三方依赖；dart:io 已在使用，跨 Windows/macOS/Linux/移动端安全）。

## 总体策略

将匹配逻辑重构成"纯函数匹配引擎 + IO 编排服务"两层：引擎只依赖文件名与少量元数据，便于穷举边界单测；服务负责目录枚举、stat 与受限的文件时长解析。对外提供"全量候选（含 eligible/score 标注，供手动面板）"与"自动匹配 Top-N（供自动加载/默认绑定）"两个视角，所有调用方统一消费，从根源消除现在 5 处调用点各取 first 的隐式行为差异。

## 算法设计（核心）

### 1. 归一化与 Token 化

- Unicode NFKC、统一转小写、全角转半角（含（）【】与 []()、全角空格等）；
- 以非字母数字为界切分 token 序列；保留"去全部分隔符后的 canonical 串"用于全等比较（兼容 `Star.Wars`/`Star Wars`/`StarWars` 相互匹配）。

### 2. 名称结构解析（解析出可解释与不可解释片段）

- 语言 tag 表（尾部）：zh/chs/sc/zho/zh-hans/zh-cn/chi/simplified/简/中/中文/汉，cht/tc/zh-hant/繁，en/eng/英文，以及 ja/jp/日、ko/韩等常见语种；`[中文]`、`[English]`、 `[简]` 括号包裹形式同表；
- 附加语义 tag 表（尾部）：forced/foreign/sdh/cc/hi/default/full/normal 等字幕类型；
- 发布 tag 表（视频名常见，也可出现在字幕尾部）：年份(19xx/20xx)、720p/1080p/2160p/4k、BluRay/WebRip/HDR/x264/x265/10bit/Remux 等；
- 装饰前缀（首部）：方括号/括号/书名号包裹段、常见字幕组/发布组特征段，如 `[VCB-Studio]`、`【某某字幕组】`；
- 其余无法归类的 token 视为"不可解释片段"。

### 3. 资格判定（确定性、防误配的硬防线）

对视频主干 token 序列 V 与字幕主干 token 序列 S（已剥离装饰前缀与上述 tag）做比较，仅以下情形合格：

- canonical(S) == canonical(V)（忽略分隔符/大小写/全半角的全等）；
- S 是 V 的"主干子集"且 V 多出的 token 全部可归类为发布 tag/年份/分辨率（如 `Movie.srt` 配 `Movie.2024.1080p.BluRay.mkv`）；
- V 是 S 的完整 token 前缀且 S 多出的 token 全部可归类为语言/字幕类型 tag（多语言同名字幕属此类）。
显式拒绝（防误配反例）：
- 年份冲突：V 无年份而 S 带年份（`StarWars` 不配 `StarWars.1977`），或年份不一致；
- 续集/附加词：剩余 token 含 `ii/iii/2/part2/cd2` 等而 V 中不存在对应词；
- 无词边界的字符粘连：`StarWarsBook.srt` 不配 `StarWars.mp4`（token 级判定天然拒绝）；
- 副本/重复标记：`(1)`、`- 副本`、`copy`、`.download` 等不可解释编号一律降为 B 类（仅手动可见）；
- 保留现有语义：字幕名以 `视频名.stream_N` 形式开头且视频本身不是 stream 文件时排除（B 站分 P 轨道字幕走独立关联）；对受支持扩展名但完全无关联的字幕（如目录中其它电影的）直接不合格。

### 4. 评分与排序

- 质量等级：A 类（资格判定通过，命名证据充分，可自动使用）；B 类（解释性匹配如副本后缀，仅供手动）；不合格（不进候选列表，但全量扫描仍返回供面板展示）。
- A 类内部排序键：语言权重（中文/简体 > 中文/繁体 > 无语言标记 > 英文 > 其他语言）> 名称分（精确全等最高，装饰前缀越干净越高，附加 tag 数量越少越高）> 时长接近度 > 修改时间新者优先。
- 时长接近度：字幕时长/视频时长 r 在 [0.8,1.25] 加分、[0.5,0.8)∪(1.25,2.0] 轻微降权、r<0.5 或 r>2.0 且存在其它 A 类候选时排到 A 类末位；当它是唯一 A 类候选时按"不强行匹配"原则降级为不自动（视同无字幕），仅面板可见。视频时长未知（为 0 或无法 probe）或字幕时长无法解析（图像字幕/损坏/超大文件）时该因子中性，不得因此剔除。

### 5. 阈值与"不匹配即空"

- 常量自动阈值只认可 A 类中的命名证据充分者；低于阈值即视为该目录无可用字幕，自动加载链路返回空，不产生任何降级自动匹配（符合用户"评分不够就不匹配，视同没有字幕"的要求）。
- 手动面板展示逻辑独立于阈值：只要扩展名受支持即列出，标注"建议匹配（A 类）/ 疑似不匹配"两类，用户手动选择不受自动门槛限制。

### 6. 时长解析的成本控制

- 仅对资格判定通过后的 A 类候选（通常 1-4 个）解析；srt/vtt/lrc 用逐行时间戳扫描取最大结束时间，ass/ssa 扫描 `Dialogue:` 行结束时间；单文件超过大小上限（约 10MB）跳过按未知处理；解析全部失败也按未知处理。复杂度：目录枚举 O(F)，匹配判定 O(token 长度)，时长解析 O(候选文件字节数)，开销可控。

## 已知局限

同一目录存在两个仅年份不同的视频（`Movie (2024)`/`Movie (1999)`）且只有一个无年份字幕 `Movie.srt` 时，两视频各自扫描都会命中同一字幕，属信息不足的固有歧义，单靠本算法无法消除；计划中通过时长因子尽力区分并保留此限制说明。
