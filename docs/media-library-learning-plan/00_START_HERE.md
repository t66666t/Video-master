在项目根目录把下面整段发给 Cursor。每一轮都发同一段；它会从 PROGRESS.md 的首个未完成阶段接着做。不要改成“把整个计划一次性做完”。

>
> 以当前工作区源码为准，保护已有未提交修改。禁止 reset / clean / checkout 恢复、批量格式化、擅自提交或升级依赖。先 rg 再读必要片段；大文件不要整文件阅读。

## 给执行 AI 的总指令

你是实现工程师。产品目标是让用户迅速找到新导入、未看完和已归档的媒体。根据本计划修改代码，不另行发明学习平台。

1. 首次读取本文件、[CONTRACT.md](CONTRACT.md)、[PROGRESS.md](PROGRESS.md)，然后只读当前阶段文件。
2. 当前真实源码优先于本计划中的历史定位。仓库无 AGENTS.md。若事实已变化，更新交接，不覆盖新代码来迎合旧描述。
3. 本计划对照基线是 HEAD `61018752`（Fluent player 4.4），当时工作区干净。实施时重新看 git status；用户新改动必须保留。禁止 reset、clean、checkout 恢复、批量格式化、擅自提交或升级依赖。
4. 先 rg 定位符号，再读相关函数及直接调用者。`home_screen.dart`、`collection_screen.dart`、`library_service.dart`、`media_playback_service.dart`、`video_action_buttons.dart`、`portable_transfer_service.dart` 都很大，禁止作为默认动作整文件阅读。每次建议读取 100—220 行；初始阅读通常 3—6 个文件，证据需要时逐步扩大。
5. 不读播放器解码、字幕渲染、OCR、原生平台、模型资产等无关内容。文档《项目介绍.md》可能落后，不作为必读。
6. 复用 4.4 已落地的布局、搜索、选择态、导入表和 FluentPack。禁止重新设计全部卡片、复制巨型页面、整理出第二套顶栏动作，或为了新入口改写播放状态机。
7. 一个阶段只交付本阶段功能和必要测试。若后续阶段尚未提供依赖，可以保留明确内部接口，但不得暴露可点击的空功能或假数据。
8. 实施前简短说明本阶段目标和阅读文件；完成后报告行为变化、验证结果、剩余问题。普通实现选择自行决定，不反复请求确认；只有真实产品冲突或无法安全继续时才提出一个具体问题。
9. 写回 PROGRESS.md，详细验证结果放 validation/Sxx.md。完成验收才标 done。当前环境不能验证的项目写 NOT RUN，不能写通过。静态阅读不等于测试通过。
10. 默认阶段结束即停，方便用户换新上下文继续。这是执行节奏，不是每阶段都要审批的要求。
