# S10：失联本地文件的单项重新定位

依赖 S09。这是有限恢复能力，不做全盘扫描、模糊匹配、批量重关联或下载资源重建。

## 先判断已有能力

定位 media_playback_service.dart 的 isSourceMissing / markCurrentSourceMissing / 缺失源打开行为；查看三种播放器页面的缺失源提示片段。
检查 LibraryService 是否已有更换源路径的方法，有则复用。只读 addSingleVideo 的资源所有权约束，不调用它来创建替代媒体。
相关测试：media_playback_missing_source_test.dart、playback_queue_policy_test.dart、media_playback_request_race_test.dart。

## 行为

1. 本地源失联保留原媒体ID、目录、进度、固定/隐藏和字幕记录；提示“文件找不到”，提供“重新定位文件”。网络失败或B站缓存缺失不能错误进入本地重定位流程。
2. 用户为这一个媒体显式选择一个可访问的同类型媒体文件；取消完全无副作用。选择后显示原标题和新文件名，确认关联；这是替换源关联，不是再次导入。
3. 新路径可读且验证通过后再提交关联；失败保持旧记录。沿用原文件选择和长期访问/私有存储策略，不随意把临时cache路径当永久来源。
4. 保留用户关联的托管字幕、固定与目录身份；与旧源绑定的兼容转码路径/生成预览等缓存不得误用于新源。仅按既有安全清理规则失效化派生缓存，不删除原文件或用户选中的新文件。
5. 更新必要的来源指纹与时长/章节信息，位置超出新时长时安全截断并提示。不能顺手删除用户字幕或把它们移动到另一个卡片ID。
6. 活动 addedAt/批次不变，lastPlayedAt不因重定位更新。
7. 当前项正在占用播放器时，使用已有带请求身份的资源释放/重开入口；若用户已经切到另一个媒体，迟到的重定位回调不能停止新媒体或将其替换。
8. 重定位不自动开始播放；用户点击继续后才沿原目录队列播放。原队列中失联项变得可用后按既有策略刷新。
9. 删除仍使用回收站；不再显示仍仅隐藏快捷记录，三种操作文案不能混淆。

## 验证

单项失联→取消/选错类型/成功；路径验证失败不改库；进度和托管字幕保留；新文件更短的处理；关联后不是新导入；正在播放A时用户切B的竞态；在线媒体不会出现本地关联动作。
使用临时文件与可替换探测器，不修改真实媒体。
运行缺失源/队列/请求竞态/私有导入的相关测试。Windows实际文件选择可验证则执行；Android/iOS/macOS无法现场验证必须记录NOT RUN，不能因为桌面通过就声明全平台恢复完成。
若平台文件访问需要扩大原生代码范围，先在交接记录具体缺口，不自行重写原生分享协议；依照本阶段目标给出最小后续修复。
